# Security Policy

## Supported versions

| Version | Supported |
| --- | --- |
| 1.0.0-beta | Yes |
| 0.1.0 | No |

Security fixes go into the latest release. Upgrade before reporting if you can.

## Reporting a vulnerability

Report privately through GitHub: the repository's **Security** tab, then **Report a vulnerability**. Do not open
a public issue, pull request or discussion for a security problem.

Include:
- the affected plugin and version, and the Paper version;
- the impact (for example item duplication, economy abuse, permission bypass, data exposure, crash);
- steps to reproduce, and a proof of concept if you have one;
- whether the issue needs a proxy network or happens on a single server.

## What to expect

- Acknowledgement within 7 days.
- An assessment and, for a confirmed issue, a fix plan or workaround.
- Credit in the release notes if you want it.

Please give a reasonable time to fix the issue before disclosing it publicly.

## Scope

In scope: the plugins, datapacks, setup script and network scripts in this repository. Out of scope: third-party
plugins (report those upstream) and misconfigured servers, such as backends reachable without the proxy.
